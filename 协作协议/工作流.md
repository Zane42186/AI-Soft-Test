# 工作流标准流程

## 核心原则

DeepSeek（大脑）和 Codex（双手）在同一个对话中协作——**我规划的同时就能执行**。

Claude Code（参谋）在你切换到 VS Code 时独立使用，提供外部审查意见。

---

## 流程一：新模块启动

### 触发条件

你在 Codex 中说"我要学{新模块}"。

### 步骤（全在 Codex 一个对话内完成）

| 步骤 | 操作 | 谁在做 |
|------|------|--------|
| 1 | 读取 STATUS.md 和现有 Conclusion 文件，恢复项目上下文 | Codex |
| 2 | 用 DeepSeek 推理能力设计该模块的学习路径：天数安排、知识要点、练习设计 | 大脑（Codex 底层） |
| 3 | 创建 `{模块}.md` 教学文档，按计划逐天填充内容 | 双手（Codex） |
| 4 | commit + push 到 Git | 双手（Codex） |
| 5 | 在对话中通知你"模块已就绪，可以开始学习" | Codex |

---

## 流程二：日常学习循环

| 步骤 | 谁做 |
|------|------|
| 1. 你打开新 Codex 对话，说"继续学第 X 天" | 你 |
| 2. 我读取 STATUS.md + 对应模块文档，恢复上下文 | Codex |
| 3. 我当日教学内容讲解 + 提供课后练习和自检清单 | Codex |
| 4. 你学习知识，在练习区填写答案 | 你 |
| 5. 你说"评审第 X 天练习" | 你 |
| 6. 我执行 learning-review Skill，逐题评审 | Codex |
| 7. 评审报告追加到 `{模块}学习历程问题.md` | Codex |
| 8. 你根据反馈修正，也可以切换到 VS Code 用 Claude Code 做二次确认 | 你 + Claude Code |
| 9. 你说"总结当前内容"，我执行 conclusion-skill 归档 | 你 → Codex |

---

## 流程三：Claude Code 协助审查

### 什么时候用

- 你想确认教学内容是否准确
- 你需要第二意见来对比自己的理解
- 你想做多源调研验证某个知识点
- 你的练习答案和我的评审有分歧

### 怎么用

1. 切换到 VS Code
2. 打开 `{模块}.md` 或 `{模块}学习历程问题.md`
3. 在 Claude Code 插件中输入你的问题
4. Claude Code 输出审查意见
5. 你带着反馈回到 Codex，我据此优化

### Claude Code 在 VS Code 中的推荐用法

| 你想做什么 | 对 Claude Code 说 |
|-----------|------------------|
| 审查教学内容 | "审查这个教学文档的内容完整性和准确性" |
| 验证我的评审 | "这个评审意见对吗？有没有遗漏的点？" |
| 深度调研 | "/deep-research {某个知识点}" |
| 安全检查 | "/security-review" |

## 流程四：对话总结与上下文归档

| 步骤 | 谁做 |
|------|------|
| 1. 你说"总结当前内容" | 你 |
| 2. 我读 Conclusion/.summary_record.json，判断增量/全量 | Codex |
| 3. 生成 00x总结.md + 更新状态文件 | Codex |
| 4. git pull → add . → commit → push | Codex |
| 5. 输出完成回执 | Codex |

---

## 核心原则总结

1. **你只需要在 Codex 和 VS Code 之间切换**，不需要开三个窗口
2. **我在 Codex 里既当大脑又当双手**，规划完直接执行
3. **Claude Code 是参谋**，你遇到瓶颈或不放心时切换到 VS Code 用它
4. **Git 是数据总线**，随时 commit + push 确保不丢进度
5. **每模块新对话**，通过 STATUS.md + Conclusion 恢复上下文
