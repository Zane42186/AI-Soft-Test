# AI Soft Test — 三 AI 协作协议

## 项目定位

这是一个以 **DeepSeek 为大脑、Codex 为双手、Claude Code 为参谋** 的 AI 辅助软件测试学习系统。
Git 和 Markdown 文件是三个 AI 之间的协作语言。

**核心理念**：每个 AI 做自己最擅长的事，通过 Git 提交传递工作成果，每新模块开启新对话以避免上下文污染。

---

## 三 AI 角色速览

| AI | 角色 | 擅长领域 | 典型输出 | 调用方式 |
|----|------|----------|----------|----------|
| **DeepSeek** | 大脑 | 深度思考、规划、分析、设计 | 学习计划、测试策略、知识框架 | 独立对话（Web/API） |
| **Codex** | 双手 | 实现、文件操作、命令执行 | 教学文档、Skill 文件、代码 | Codex Desktop App |
| **Claude Code** | 参谋 | 审查、调研、咨询 | 评审报告、优化建议、研究结论 | Claude Code CLI/Desktop |

## Git + Markdown 通信协议

### 核心原则

1. **Git 是共享总线**：所有工作的输入、输出都通过 Git 提交传递。一个 AI 写完文件经过 commit + push，另一个 AI pull 后继续。
2. **Markdown 是标准格式**：所有文档、计划、评审、总结都用 .md 文件，以 UTF-8 编码、中文撰写。
3. **文件所有权清晰**：每种文件类型有明确的归属 AI，避免冲突。
4. **提交信息即消息**：commit message 是 AI 之间传递信号的方式。

### 文件所有权矩阵

| 文件模式 | 归属（写） | 可读 | 说明 |
|----------|-----------|------|------|
| {模块}.md 教学文档 | Codex | 全部 | 模块的教学内容、练习、自检清单 |
| {模块}学习历程问题.md | Codex | 全部 | 每日练习的评审反馈归档 |
| 协作协议/*.md | Codex | 全部 | 协作协议文档，由 Codex 维护更新 |
| 学习计划/策略 | DeepSeek | 全部 | Brain 输出的规划文档 |
| 评审/调研报告 | Claude Code | 全部 | Advisor 的审查输出 |
| Conclusion/*.md | Codex | 全部 | 对话总结归档 |
| STATUS.md | Codex | 全部 | 项目状态快照，用于新对话上下文恢复 |

### 提交信息约定

提交信息是 AI 间传递信号的关键媒介，格式如下：

```
<文件/模块>: <做了什么>

可选：补充说明、交接标记、待办提醒
```

示例：
```
MySQL: 创建教学文档 Day 1-3

@Codex 教学文档已就绪，可以开始评审
```

### 协作模式选择

根据任务复杂度，可选择两种协作模式：

| 模式 | 适用场景 | 典型流程 |
|------|----------|----------|
| 串行（推荐） | 新模块启动、重要交付 | A 做完 commit，B pull 后继续 |
| 并行 | 独立工作、日常教学 | 各 AI 在独立对话中工作，最后合并 |

建议新模块首次启动用串行，日常教学中各 AI 在独立的对话里并行工作。

## 如何避免上下文污染

### 新模块 = 新对话

每个学习模块启动时开启全新的 AI 对话（三个 AI 各开一个新对话）。
这样旧模块的上下文不会干扰新模块。

### 新对话的上下文恢复流程

当在新对话中启动时，AI 按以下顺序读取上下文：

1. STATUS.md（项目根目录）— 30 秒了解项目当前状态
2. 协作协议/README.md — 了解自己的角色和协作规则
3. Conclusion/对话压缩总结.md（如有）— 恢复历史上下文
4. 相关计划文件（如有）— 当前任务的详细规划

### Git 操作顺序（每次开始工作前）

```
git pull               # 拉取其他 AI 的最新成果
# ... 工作 ...
git add .
git commit -m "<模块>: <做了什么>"
git push                # 推送成果给其他 AI
```
