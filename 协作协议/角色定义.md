# 角色定义：三 AI 协作分工

## 概述

本文档定义 DeepSeek、Codex、Claude Code 三个 AI 角色在软件测试学习系统中的分工。
与常见理解不同，**DeepSeek（大脑）和 Codex（双手）不是两个独立的对话窗口**，而是同一个 Codex 对话中的两个层次——底层模型（DeepSeek）和能力层（Codex）。

---

## 架构分层

```
┌─────────────────────────────────┐

│                                 │
│  Codex Desktop App（对话界面）    │
│                                 │
│  ┌───────────────────────────┐  │

│  │ - 执行 Git 命令             │  │

│  │ - 读写工作目录              │  │
│  ├───────────────────────────┤  │
│  │ DeepSeek 推理层（大脑）     │  │  ← 由 litellm 代理提供

│  │ - 知识体系设计              │  │
│  │ - 分析错误模式              │  │

│                                 │
├─────────────────────────────────┤
│                                 │
│  VS Code（另一个工具）           │

└─────────────────────────────────┘

         Git + GitHub（共享数据总线）
```

## 三个角色的实际运作方式

| AI 角色 | 实际位置 | 做什么 | 怎么调用 |
|---------|---------|--------|---------|
| **DeepSeek（大脑）** | Codex 的底层推理模型 | 深度思考、规划路径、设计知识框架 | 不需要单独开对话——我在 Codex 中思考时就在用 DeepSeek |
| **Codex（双手）** | Codex Desktop App | 写文件、运行命令、执行 Git、生成文档 | 你当前就在和我对话——我就是 Codex |
| **Claude Code（参谋）** | VS Code 插件 | 审查内容质量、做调研、提供第二意见 | 你切换到 VS Code，用 Claude Code 插件操作 |

---

## 典型任务分配

### 我（Codex）在一个对话中完成

- 规划模块学习路径（大脑能力）
- 创建教学文档和练习题（双手能力）
- 教学过程中讲解知识、示范案例
- 评审你的练习答案（learning-review Skill）
- 对话结束时归档总结（conclusion-skill）

### Claude Code（VS Code 插件）做

- 审查我写的教学文档，发现盲区
- 用 /deep-research 做多源调研验证知识点
- 当你遇到复杂问题时提供另一种思路
- 做安全审查和代码质量检查

## 协作时序示例

### 场景：启动 MySQL 模块

```
你在 Codex 中告诉我："我要开始学 MySQL 了"
  ↓
我（Codex，大脑+双手）：
  1. 用 DeepSeek 推理能力规划 MySQL 学习路径（3-5 天）
  2. 创建 MySQL.md 教学文档，写入 Day 1 内容 + 练习
  3. commit + push 到 Git
  ↓
你学习 Day 1，做完练习
  ↓
你告诉我："评审第 1 天的练习"
  ↓
我（Codex）执行 learning-review Skill，生成评审报告
  ↓
你想确认内容质量，切换到 VS Code
  ↓
Claude Code（参谋）审查 MySQL.md，发现某个概念讲解不够透彻
  ↓
你带着审查反馈回到 Codex，我据此优化内容
```
